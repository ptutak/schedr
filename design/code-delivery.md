## Current

### What is parsed

- **A DAG is held while its file fails to import** (D72): Non-transient file errors hold every DAG
  of that file, including InvalidDag, InvalidPath and ParseResultTooLarge; these rejections are not
  retried. Held DAGs create no runs, reject manual triggers and leave queued runs waiting; running
  runs continue, and missed fire times follow catchup after repair. ParseTimeout and RunnerDied hold
  nothing; transiently failed files retry indefinitely, starting after 30 s and doubling to 10 min,
  preferring another worker. Holds and their file-level reasons appear in the API, UI, CLI, metrics
  and logs.
- **Each parsed file records its worker and parse time** (D93): Each parse_files row records the
  worker_id and parsed_at for that file. A retry records its own worker and time.
- **Only Python files mentioning schedr are parsed** (D305): Python files containing the exact bytes
  `schedr` are parsed; other files are shipped and hashed but skipped. Unreadable files are parsed
  to report the error; `schedr dags check` follows the same rule and reports skipped files.
- **DAG files use ordinary Python imports in separate processes** (D326): Each parsed file has its
  own process and ordinary module name; tasks import it the same way. Python import behavior
  applies, and dots in file or folder names are refused.
- **A DAG belongs to the module running its with block** (D329): The module running a DAG’s with
  block owns it, including when a helper function builds it. An imported module owns its own DAG,
  and the file must mention schedr.

### Roots and the scan

- **Parse jobs and tasks run from a read-only copy of the hashed code** (D102): The agent copies
  scanned root files into its data directory and hashes the copied bytes. Parse jobs and tasks
  import from the read-only copy; unused older copies are removed and bytecode is not used.
- **Standalone takes --dag-path and --script-path** (D488, planned (M5.1n)): `schedr standalone`
  takes `--dag-path PATH` and `--script-path PATH`, each repeatable and taking `.`; given, a list
  replaces `SCHEDR_DAG_PATH` / `SCHEDR_SCRIPT_PATH` and the file's `[dags] path` / `[scripts] path`,
  as other options override. A root given as `.` is named after the folder it is, as any other path;
  the lists keep their rules (decision 299). Only the standalone role takes them. Not chosen:
  `--cwd-dag-path` / `--cwd-script-path` (`.` says it), adding to the lists, a fixed name for `.`,
  the worker role too.

### Conflicts

- **A DAG conflict remains while the remaining file fails to import** (D107): When the stored
  version belongs to the removed file, a conflict remains until the remaining file imports. The
  master logs a warning; a stored version belonging to the remaining file is kept.

### Versions

- **A worker's move to new code or a revert makes that hash newest** (D113): A worker’s move to an
  unseen hash or one recorded before the hash it left makes that hash newest; moving to a later-
  recorded hash is catching up. Compare with the worker’s previous report, including across
  reconnects. An unseen hash is newest on first report; a revert while the master was down is not
  detected as a switch.
- **A DAG root’s version includes the other roots on its path** (D327): Other DAG roots’ content
  hashes fold into a root’s reported hash, so any root edit reparses the others. Workers serving a
  root must agree on the DAG roots on its path. A lone root keeps its plain hash.

### When a file fails

- **Reject DAG IDs that are dot or dot-dot** (D127): DAG IDs cannot be `.` or `..`. A file defining
  either ID receives an import error explaining why.

### Imports

- **Ambiguous import names fail only files that use them** (D328): A top-level name duplicated
  across roots or colliding with a standard, installed or preloaded library fails the conflicting
  file and root files importing it, with an explanation. Checks occur at compile time, including
  inside functions, independently of process start method. Other files and tasks continue; library
  imports receive the library.

### Local checks

- **DAG checks use the shipped copy filtered by .schedrignore** (D330): dags check reads the same
  filtered copy as dags test and workers. Files excluded by .schedrignore are unavailable for
  imports.
- **A named file inside a DAG root keeps that root** (D331): Checking a named file or folder within
  a configured root retains its module path and other roots. A named file that a worker does not
  receive is an error.
