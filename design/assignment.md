## Current

### Limits and mapped tasks

- **Concurrency limits use run and current DAG versions** (D87): `max_active_per_run` comes from
  each run’s own DAG version. Across-run `max_active_tasks` and `max_active` come from the current
  DAG version.
- **Mapped instances each count toward concurrency limits** (D89): Each mapped instance counts
  toward all three task concurrency limits. The whole-task `-1` row does not count.
- **Concurrency limits cannot be overridden through the API or CLI** (D95): Changing a concurrency
  limit without a code change has no API or CLI override. Limits shared across DAGs are a proposal
  for M6.

### Placement and ordering

- **The master keeps concurrency counts in memory** (D88): The master counts running, cleaning-up
  and assigned-not-started instances per DAG and task. It rebuilds counts from the database at
  startup and checks them on assignment.
