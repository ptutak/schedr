# protocol

## Current

### Messages and limits

- **A worker message turn shares one transaction** (D54, planned (M4B.3)): Planned for M4B: eligible
  messages in one worker turn share a transaction, with a savepoint and memory snapshot per message.
  A failed message is undone alone; a failed commit restores the turn and replays messages
  individually. Metrics, wakes and replies follow commit; heartbeats/warnings stay outside, while
  `CodeVersionChanged`, `Draining` and `Deregister` end the batch and run alone.
- **The worker message size limit is configurable** (D58): `[grpc] max_message_size` limits worker
  messages, defaults to 64 MiB and ranges from 4 MiB to 1 GiB. The master announces it to workers in
  `Registered`.
- **Oversized task results fail before they are sent** (D61): DAG loading rejects task output limits
  that cannot fit in a worker message. An oversized finished result becomes an unretried
  `output_too_large` failure before journalling.
- **Parse results stream one file per message** (D62): `UploadParseResult` streams a header followed
  by one message per file. An oversized file is uploaded as `ParseResultTooLarge`; uploads run
  independently of heartbeats.

### Connection

- **The master acknowledges each worker heartbeat** (D258): The master answers each `Heartbeat` with
  `HeartbeatAck` as it arrives. The response is not behind the master’s lock and is not sent while
  paused.
