## Current

### Roles

- **The federated UI is a separate schedr ui role** (D21): `schedr ui` is a separate role federating
  any mix of distributed deployments and SQLite or Postgres standalones through their JSON APIs. It
  can deploy alone from the chart; standalones can run with `--no-ui` and prove the UI’s calls
  through a shared token. Webservers continue serving the API.
- **A recorded task finish wakes a scheduler round** (D42): A recorded worker `Finished` wakes the
  master’s loop to dispatch downstream tasks. Bursts coalesce into one wake, and a woken round
  starts at least 50 ms after the previous round ended.
- **Task finishes and commands wake a scheduler round** (D43): Besides the regular tick, a worker's
  `Finished` and a command notification wake a scheduler round. A new worker’s registration waits
  for the next regular tick.
- **A master that is not leading is unready and refuses streams** (D297): A paused or superseded
  master returns 503 from `/readyz` until it leads again. It refuses worker streams with the gRPC
  status unavailable (`Status::unavailable`), including registrations that waited for its lock while
  it paused.
- **One leading master per deployment; scale by more deployments** (D382): A deployment has one
  leading master and standby masters ready to take over, as now. Scheduling is never sharded across
  leaders: more load means more deployments.

### Other

- **B48 is fixed by M4B's per-group memory snapshot** (D451): B48 (each worker message copying the
  dispatcher's whole memory) is fixed by M4B.3: a turn's group takes one memory snapshot, not one
  per message, and rollback stays as it is. Not chosen: a narrower snapshot per message now; waiting
  for stress to show it.
- **A master that isn't leading names the leader** (D452, planned (M4B)): A master that isn't
  leading refuses a worker's stream with UNAVAILABLE naming the lease holder and when its lease
  expires, for operators reading the worker's log. Not chosen: as before, "not leading" alone.
