## Current

### One trigger

- **A trigger runs as a hidden sensor without an attempt** (D348): A trigger runs on a watcher slot
  as a hidden sensor, without a graph node or attempt. Events are acknowledged after storage; the
  trigger resumes from its bookmark and restarts on code changes.
- **`EventNamed` waits for events posted through the API** (D354): Named events can trigger DAGs or
  be awaited by nodes, sensors and trigger functions. Waits match events posted since run creation;
  triggers start at most one run per name and key.

### `@trigger` and `@trigger.poke`

- **Trigger failures, stopping and restarts retain their state** (D349): Poke errors retain the
  bookmark; returned generators stop until code or version changes. Queue limits and idle restarts
  govern running triggers, whose strikes and consecutive errors persist.
- **`@trigger.poke` batches events in Python** (D352): `@trigger.poke(batch=...)` gathers a window
  in Python and stores each item individually. One run receives only its new items as
  `list[Event[T]]`, keyed by the last new item; no new items means no run. The bookmark advances to
  the window's last key, including a repeat. Replaying an individual key produces a singleton batch.

### Manual runs, CLI and tests

- **Triggers have endpoints, manual event runs and test helpers** (D350): Trigger API and CLI
  endpoints show, restart and switch on triggers and list events. Manual runs supply an event; test
  helpers and the DAG page expose trigger events.
