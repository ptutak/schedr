### Database and schema

- **Replace NUL in database JSON strings and keys** (D114): The database layer replaces NUL with
  U+FFFD in every string and key of JSON it writes. JSON without NUL is written unchanged.

### Retention

- **Retention always keeps each DAG's three newest runs** (D430): Besides unfinished runs, never
  deleted per DAG: its newest scheduled run (the scheduler's chain: without it a catchup DAG would
  create its runs again from `start`), its newest run of any kind (a manual run's `since`), and the
  last that ended `success` or `failed` (`RUN_RECOVERED`). This replaces the archived "the latest
  run of each DAG".
- **A chained run loses its parent link when the parent is deleted** (D431): A run's `parent_run_id`
  (a `TriggerDagOperator`'s child) is cleared when retention deletes the parent, which usually ages
  out first; `triggered_by` still names the parent run. A parent isn't kept for its children, nor
  deleted with them.
- **Retention's interval and batch are hidden values** (D432):
  `SCHEDR_HIDDEN__MASTER__RETENTION_INTERVAL` (1h) and `SCHEDR_HIDDEN__MASTER__RETENTION_BATCH` (100
  runs per transaction), as D232's timings; `[retention]` holds only the ages: `runs`, `outputs`,
  `events`, `commands`. This replaces the archived public `interval` and batch keys.
- **Retention is on by default** (D433): `[retention]` defaults as archived: `runs`, `outputs` and
  `events` 90 days, `commands` 365 days; `outputs` and `events` default to `runs` when only it is
  set; `"forever"` turns any of them off. An upgraded deployment starts deleting what is older at
  once.
- **Named events go with `[retention] events`** (D434): Events posted through the API
  (`named_events`, D354) are deleted after `[retention] events`, as trigger events are, by when they
  were posted; what triggers passed of them goes with them. No key of their own.
- **An output deleted by retention answers 410 Gone** (D435): `GET
  /api/v1/runs/{run}/tasks/{task}/output` answers 410 "output deleted by retention" for a task whose
  output `[retention] outputs` removed; 404 still means it never had one. The run, its tasks and
  their outcomes stay; the UI shows that text.
- **Retention also keeps the runs catchup counts as done, and runs still read** (D440): Besides
  D430's three newest runs, kept per DAG: its successful manual and backfill runs planned after its
  newest scheduled run, and, while it has no scheduled run, its successful backfill runs (catchup
  counts their fire times as done; deleted, it would run them again). Kept whatever the DAG: a run
  an open `TriggerDagOperator` attempt waits for (deleted, it would be started again), a run or
  posted event a waiting step or trigger was handed (its retry gets the same). A removed DAG keeps
  these until its removal is as old as `[retention] runs` (a file missing for a while costs no
  history). Found by Codex's review of M4.14; the never-scheduled case and the removed DAG's raised
  by side notes to the user.
