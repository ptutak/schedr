## Current

### Waiting for runs

- **`RunOf` waits for or triggers from another DAG’s run** (D353): `RunOf` selects another DAG's run
  or task; lagged waits use this run's `planned_for` minus lag and choose the newest matching run by
  `triggered_at`. The master-ended node yields a run ID or `TimedOut`; failed, cancelled or skipped
  targets yield routed `Failed`, otherwise failing the node and run. No-code triggers start runs
  only for successful completions while live, without catching up paused periods. Function sensors
  and triggers receive `RunResult[T]` on watcher slots for all terminal states; sensors may return
  `NOT_YET`, and failed calls retry the same handed run, with trigger retry limits or manual skip
  available.

### Building it

- **Build the trigger operator and backfill in two parts** (D357): M4.12a builds

### TriggerDagOperator

- **`TriggerDagOperator` gives the target run’s ID** (D358, planned (M4.12a)): The operator’s value
  is the target run’s ID, whether or not `wait=True`. The target’s output can be read with a `RunOf`
  sensor or the API.
- **A failed target gives a routable `Failed` outcome** (D359, planned (M4.12a)): A failed,
  cancelled or skipped target gives `Failed`, including its state. The DAG can route it with
  `.on(Failed)`; otherwise the operator task fails.
- **`max_wait` times out without cancelling the target run** (D360, planned (M4.12a)): When the
  operator’s `max_wait` expires it yields `TimedOut`. The target run continues.
- **An operator retry starts a new run only after failure** (D361, planned (M4.12a)): A retry starts
  a new target run only after the previous run failed. The run is created and recorded on the task
  in one transaction.
- **A triggered run accepts an optional `planned_for`** (D362, planned (M4.12a)): `planned_for`
  accepts a datetime or a reference and defaults to the parent’s planned time. Airflow’s
  `logical_date` maps to it.
- **Tasks start runs with `TriggerDagOperator`** (D365, planned (M4.12a)): Tasks start runs with
  `TriggerDagOperator`. The task routes of `schedr.api` remain limited to events.
