## Current

### Size and ports

- **Deploy schedr ui by default in the distributed chart** (D37): The distributed chart deploys one
  UI replica and a Service on port 8082. Its default deployment is the release’s webserver; no
  Ingress is created.

### Images

- **A slim image beside the full one** (D383): Besides the full image (every connection type, D212,
  the default), 1.0.0 ships `schedr-slim`: Python and schedr without the database and SSH clients.
- **Images on glibc beside Alpine; Alpine tagged -alpine** (D454): From 1.0.0 each image (`schedr`,
  `schedr-slim`, `schedr-server`) is built twice for x86_64: on glibc from the manylinux wheel,
  `python:3.14.8-slim` (Debian), the plain tag (`1.0.0`, `1.0`), and on Alpine from the musllinux
  wheel, tagged `-alpine` (`1.0.0-alpine`, `1.0-alpine`). The plain tag meant Alpine in 0.1.0. The
  glibc base image takes PostgreSQL 18's client from PostgreSQL's apt source (Debian 13 has 17,
  whose `pg_dump` refuses an 18 server). Not chosen: a suffix for glibc; separate image names;
  Ubuntu; distroless.

### Upgrades and compatibility

- **Upgrade-rule gaps: the clear ones fixed, the others asked** (D439): M4.15's check of the upgrade
  rules against what M2 built fixes the gaps the archived rules (Upgrades and compatibility) settle;
  a gap needing a choice stops the step for the user, with what was done committed.
- **A DAG that no longer parses after a major upgrade is held** (D441): As any file that fails to
  import (D72): every DAG of the file is held, no new runs, manual triggers refused, running runs
  finish. The hold's reason names the schedr version the file failed with and says to fix the file
  or roll back. Not chosen: keeping the older parse in use (the archived design's "last good version
  keeps running").
