## Current

### Routing

- **An unchosen branch edge counts as skipped** (D55): A branch returns downstream task handles;
  each unchosen selection edge counts as skipped. The target’s trigger rule considers its other
  edges, and an empty selection is allowed.
- **A task starts after all its upstream tasks end** (D345): A task starts after its upstream tasks
  have ended. To act on the first of several, use a `first_of` node.

### Mapped tasks

- **Mapped task state follows its instances** (D75): An exhausted instance failure or lane-upstream
  failure immediately ends the mapped task and cancels its other instances. Running instances are
  stopped; late results are ignored and their outputs are not stored. The task is failed, or
  upstream_failed when only lanes failed; otherwise its run_if evaluates all finished instances.
  NONE_FAILED skips only when all instances skipped; ALL_SUCCEEDED skips when any skipped; zero
  instances succeed with [].
- **Mapped outputs are stored per instance** (D77): A mapped task’s output is stored per instance. A
  downstream list is assembled on read in map-index order, with `None` for skipped instances.
- **Mapped output outcome selection stays per element across a whole edge** (D119): An .on(...)
  selection on a mapped output checks each element even when another use makes the edge whole. After
  the whole upstream finishes, instances with other outcomes or skips are skipped.
- **An outcome-filtered order edge from a mapped task counts each instance** (D120): An .on(...)
  order edge from a mapped task contributes one edge per instance, taken when that instance ends
  with a selected outcome. Downstream run_if combines these with its other edges: NONE_FAILED
  permits any matching instance, ALL_SUCCEEDED requires every instance to match. An empty mapping
  takes the edge.

### Retries

- **A command's retry doesn't depend on its exit code** (D389): A declared exit code is a success
  and isn't retried; any other code fails the attempt, retried as usual. There are no per-code retry
  rules.

### Notifications

- **No notification for a task running too long** (D390, planned (M4.13)): Notifications have no
  long-running or SLA event; a task's `timeout` stops one that runs too long.
- **Notifications go by email and a generic webhook** (D391, planned (M4.13)): Notification channels
  are email and a generic JSON webhook; there are no dedicated Slack or Teams channels.
