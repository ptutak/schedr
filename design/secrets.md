# secrets

Secret storage and masking.

Generated by `make records` from the decisions whose `topic` (or `also`) is this one; edit the decisions, not this page.

## Current

### Masking

- **Mask task logs and outputs when shown** (D131): The webserver masks log text and output texts,
  names and fields named by secret words when shown. Log parts use whole lines and 64 KiB of
  preceding masking context; UI and CLI use 1 MiB parts, with oversized lines visibly cut and their
  remainder skipped. Ordinary downstream tasks receive stored outputs, already masked for secret
  values by the agent under D167; `RunOf` readers receive API- masked outputs.
- **Secret values are masked in outputs before storage** (D167): The agent masks secret values in
  attempt outputs and error summaries before they leave the worker. Downstream tasks receive `****`;
  masking writes a warning naming the secret and replacement count.
- **Vault non-string values are read and masked as JSON text** (D171): Vault KV v2 values that are
  not strings are read as JSON text. The resulting text is masked as a secret.

### Using secrets

- **Failed on-demand secret reads can set the attempt error kind** (D168): A failed on-demand secret
  read fails the CLI call or raises in Python and is remembered. If the attempt fails without its
  own error kind, the secret’s kind fills it; success remains success.
- **Secrets are typed as their values** (D176): Indexing a secret path gives a dict; indexing a key
  gives a string. `secrets.value('path#key', default=...)` gives a string; task context has matching
  methods. Indexing a `path#key` is refused when the file loads.
- **schedr.text marks a t-string as a string for Python tasks** (D177): `schedr.text(t'...')` marks
  a t-string passed where a Python task takes a string. It is typed as `str`.
- **secrets= accepts strings and placeholders** (D178): `secrets=` accepts plain path or path-and-
  key strings. It also accepts whole-secret and key placeholders.

### Storage and keys

- **schedr secrets new-key generates a secret key** (D169): `schedr secrets new-key` prints a new
  `SCHEDR_SECRET_KEY`. The key is 32 random bytes encoded as base64; rotation is not built now.
- **Secret export writes one JSON file per secret** (D170): `schedr secrets export --to DIR` writes
  each secret to `DIR/<path>.json` with mode 0600. It refuses a nonempty directory and prints no
  secret values to the terminal.
- **Multiple secret storages require an explicit default** (D172): Startup refuses several storages
  without `[secret_storage] default`. A single storage is the default; standalone uses `db` when
  none is configured.
- **Teams requiring isolation run separate deployments** (D173): A task can use its worker's Vault
  login and access its role's allowed paths. Teams kept apart use separate deployments; a federated
  UI can show them together.
