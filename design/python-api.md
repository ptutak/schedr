## Current

### Branches and groups

- **Dependencies on groups use their roots and leaves** (D56): `x >> group` links to its roots and
  `group >> y` links from its leaves, computed from all edges once the whole DAG is written.
  Dependencies on empty or cyclic groups fail parsing when the DAG block ends, naming where the
  dependency was written.
- **DAG JSON records task groups explicitly** (D64): DAG JSON records a top-level `groups` list and
  each task’s optional innermost group. The master validates group membership, parents and cycles.
- **A group ending in a branch connects to following tasks by order edges** (D94): A dependency from
  a group joins its last tasks, including a branch, to following tasks with order edges. Each
  following task applies its own run_if; the branch's own edges remain choices.
- **Invalid group dependencies name where they were written** (D97): A dependency on an empty group
  or a group whose tasks form a cycle is a parse error. The error is reported at the end of the DAG
  block and names the dependency's location.

### Typing

- **Type checkers read task calls as their values** (D57): DAG calls produce runtime references but
  are typed as their declared values; data-free calls use handle types, and context fields are typed
  as values. `schedr.Data` and `schedr.pydantic.Model` provide typed DAG operations; plain outcome
  classes remain allowed with `schedr.on` and a `TypingHint` warning shown by `dags check` and
  pytest. `make lint` checks example DAGs and typing fixtures with mypy strict and basedpyright;
  graph/value misuse and mapped arguments still require loading-time checks. *Not found in the code
  yet:* context fields are typed as values.

### Mapping

- **DAG JSON separates fixed and mapped arguments** (D69): Fixed arguments remain in `arguments`,
  while `expand` describes the values that vary. `product` is an ordered list of named values and
  `kwargs` contains a list of dictionaries.
- **Mapped output lanes advance per instance** (D70): An element-wise mapped-output lane expands
  after its upstream expands; instance i waits for upstream instance i. Other edges, an explicit
  order edge, or another reference to that upstream make it a whole-task barrier. Outcome narrowing
  with `.on(...)` remains per instance even behind that barrier.
- **A mapped task keeps a whole-task row** (D74): Every task has a `map_index = -1` row; for a
  mapped task it represents the task as a whole. Expansion creates runnable instances numbered
  `0..N-1`, each with its own retries and cancellation.
- **The master sends each mapped instance its elements** (D76): The master sends each instance’s
  resolved elements under $expand and mapped-upstream element outcomes under $expand_outcomes; task
  JSON is shared. The mapped list is not additionally sent whole; other inputs contain only what the
  task’s other arguments reference. Non-dict mapped-upstream expand_kwargs elements fail their
  instance at assignment, unretried, with input_mismatch. Literal expand_kwargs dictionaries have
  names and types checked at load, including overlap with partial arguments.
- **Mapped product arguments vary in written order** (D79): In expansion over several lists, the
  first argument written varies slowest. This determines map-index and gather order; DAG JSON
  preserves `product` order.
- **Build mapped elements containing templates or dag_ctx per instance** (D118): The master counts
  mapped elements containing t-strings, `dag_ctx`, parameters or secrets and sends them in stored
  form. Each instance's runner builds its element with the referenced outputs.

### Defining a DAG

- **An unmapped task limit produces a parse warning** (D90): Setting `max_active_per_run` directly
  on an unmapped task produces a parse warning shown by `dags check`. A value inherited from
  `StepDefaults` does not produce this warning.

### Values the API records

- **Shell-string commands take no placeholders** (D99): A shell-string command cannot contain
  placeholders; the DAG loader, master and agent refuse them. Values can be passed in an argument
  list or through env; :raw is removed.
