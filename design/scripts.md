## Current

### Building it

- **M4.9 delivers scripts in three reviewed steps** (D292): M4.9a delivers script roots, TOML
  checking and standalone jobs; M4.9b delivers script tasks and `ScriptOperator`. M4.9c delivers
  params, outcomes and script cleanup and resource support; each step is reviewed and documented.

### Script roots

- **The agent reads and checks schedr.toml** (D293): The Rust agent checks every `schedr.toml` key
  and builds standalone jobs as one-task DAGs; Python does not read TOML. During parsing,
  `ScriptOperator` requests checked declarations over the runner socket. Outside parsing it only
  records the reference; `schedr dags check` resolves references through `SCHEDR_SCRIPT_PATH`.
- **Script roots and DAG roots cannot share a name** (D299): A script root and a DAG root with the
  same name cause a startup error naming both paths. `[scripts.roots]` can rename a script root.
- **Workers withdraw DAG roots when required script roots are missing** (D303): A worker lacking a
  required script root withdraws the DAG root, neither parsing nor running it, and warns. The master
  omits script roots unreported by live workers after the configured five-minute grace, also
  observed from master startup; references remain import errors.
- **The master sends workers each DAG root's script roots** (D304): Parsed files persist requested
  script roots, including missing ones. At registration and on changes, the master sends each DAG
  root’s current uses, excluding script roots absent beyond D303’s grace; the recorded uses survive
  restarts.

### From a DAG

- **A changed script declaration re-parses its DAGs** (D294): A script root change re-parses DAGs
  whose `ScriptOperator`s refer to it, updating scheduling keys from the declaration. Workers run
  scripts at the script root hash expected by the master.
- **A missing script root is a parse import error** (D295): A parsing worker reports an import error
  naming a script root it lacks. Workers parsing DAGs need the script roots those DAGs use.
- **A DAG root's hash includes its used script roots** (D301): The agent folds the hashes of script
  roots used by the last parse into the reported DAG root hash. A script change causes a new DAG
  root hash and re-parse; tasks use the parsed versions of both roots.
- **ScriptOperator overrides args, env and secrets** (D302): `args` replaces the declared list;
  `env` merges variables with the operator's values winning. `secrets` adds to the declared secrets.
- **ScriptOperator references are checked during parsing** (D306): Outside a parse, `ScriptOperator`
  only records its reference. `schedr dags check` checks references against the configured script
  roots in `SCHEDR_SCRIPT_PATH`.
- **Script resources reject contradictory declarations** (D312): ScriptResource and cleanup_script
  reject declarations with outcomes; cleanup_script also rejects cleanup. A ScriptResource setup
  retains its declared cleanup for a partly failed setup.

### What a job says

- **An unscheduled script declaration is only for DAGs** (D296): A declaration without a schedule is
  not a standalone DAG or listed among DAGs; it is used through script operators and resources. Only
  `script` and `interpreter` are required, and DAG-level keys are errors.
- **A job's notify key is an import error until notifications exist** (D298): A job declaration
  containing `notify` produces an import error naming the job. The error says notifications are not
  available yet.
- **A standalone job's task has the job's name** (D300): A standalone job's one task uses the job
  name as its task ID. Job names contain only letters, digits, `_` and `-`; invalid names produce an
  import error.
- **Script job parameters have types inferred from TOML values** (D310): Job parameter types come
  from string, integer, float, boolean, date, offset-free datetime in the job’s timezone,
  homogeneous-list, or nested-table defaults. Empty/mixed lists, empty tables and times without
  dates are import errors naming the key. Triggers replace nested objects whole; parameter names
  contain letters, digits and underscores.
- **Declared script outcomes apply, while routing requires an enum** (D311): Declared outcomes
  define successful exit codes without an operator enum. An outcomes enum replaces them and enables
  enum routing and .outcome. Without one, only declared DefaultOutcome.SUCCESS can be routed on;
  other .on selections and .outcome are parse errors.
- **Script cleanup settings can override declaration defaults** (D313): ScriptOperator and
  ScriptResource cleanup settings override the declaration, then DAG defaults; the declared cleanup
  script cannot change, and cleanup_* without a declared cleanup is a parse error. cleanup_script
  options override declaration settings, then cleanup defaults: three tries, 30 seconds and the
  setup’s queue.
- **Workers reject tasks whose cleanup script they cannot run** (D314): A worker missing a task
  cleanup’s interpreter or script rejects the task with rejection 3 or 5. Cleanup scripts use their
  task’s environment and working directory. Moved or recovered cleanups require only what the
  cleanup runs, so absence of the original task’s interpreter does not exclude a worker.
