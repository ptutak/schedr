# task-processes

Rust/Python integration, how tasks start (fork server), the runner.

Generated by `make records` from the decisions whose `topic` (or `also`) is this one; edit the decisions, not this page.

## Current

### Runner and channel

- **A shim per task reports its start and exit** (D13): The fork server forks a shim for each task;
  the shim creates the task’s process group and reports its PID and exit. It reaps the task only
  after the agent closes the status socket.
- **The shim reports process usage without controlling the task** (D14): The shim reports core dumps
  and process usage with the exit status. If usage cannot be read, it reports null and still reports
  the exit.
- **Spawned process usage is read before the process is reaped** (D18): The agent reads CPU time and
  major faults from the spawned process’s zombie. Peak RSS and context switches are null; unreadable
  usage is null.

### Starting Python

- **Forked tasks run their own interpreter shutdown steps** (D15): Before exiting, a forked task
  waits for non-daemon threads and runs its own exit handlers. Inherited server handlers are
  cleared; logging shutdown and task finalizers are retained.
- **The fork server agent work is a separate plan step** (D17): M2.5.4 is split in two; M2.5.4a
  builds the agent side of the fork server. It starts and supervises fork servers and handles fork
  requests and fallback.
- **Retry fork server preload import failures for a limited time** (D19): Preload import failures
  are retried with backoff for `[worker] fork_server_import_retry`, default 20 minutes. After that
  the server stays disabled until restart; 0s disables retries.
- **Do not retry fork server thread or version failures** (D20): A disabled fork server is not
  retried for threads after preload or a version mismatch. The log reports failures and the disabled
  metric stays visible.

### Commands and supervision

- **A cancelled process group keeps its remaining grace period** (D100): If the main process exits
  during cancellation, remaining group members keep the rest of the grace period, then are killed.
  The stop ends at once when the group is empty.
- **A task's timeout counts from its launch** (D116): Timeout covers the whole attempt: secret and
  connection reads, runner or command startup, fork- server waits and request sending. The process
  receives only the remaining budget; exhaustion before launch starts no process and ends timed_out,
  removing connection files. Timeout or cancellation before hello stops the runner and ends the
  attempt accordingly.
- **Attempt timeouts include secret and connection reads** (D213): The attempt timeout includes
  secret and connection reads and runner or command startup. The process receives only the remaining
  time. If reads exhaust it, no process starts: the attempt ends `timed_out` and its connection
  files are removed.

### Interpreters

- **A worker's interpreters serve all its roots** (D385): A worker has one set of interpreters for
  all its DAG roots, never one per root. Workers are cheap: a different set of interpreters is a
  different worker with its own queues.
